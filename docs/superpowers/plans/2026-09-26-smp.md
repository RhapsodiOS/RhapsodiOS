# Symmetric Multiprocessing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the kernel on every CPU of a ppc or i386 machine: compile the Mach core with `NCPUS > 1`, add the machine-dependent half each architecture lacks (per-CPU state, `cpu_number()`, IPIs, per-CPU clocks, TLB coherence, CPU discovery, secondary start), and keep BSD and DriverKit correct by running them only on the master CPU.

**Architecture:** One machine-independent design in six phases. Phase 1 makes an `NCPUS > 1` kernel build and boot on one CPU with no behaviour change. Phase 2 adds per-CPU plumbing and master binding while still running one CPU. Phase 3 brings up secondaries on i386 under QEMU. Phase 4 does the same on ppc, on real dual-G4 hardware. Phase 5 adds TLB coherence and hardening. Phase 6 makes it the default and documents it. The Mach core (`kern/`, `vm/`, `ipc/`) is MP-safe with its existing simple locks; `bsd/`, `uxkern/`, `driverkit/` and all DriverKit drivers run on the master CPU through the existing `unix_master()` binding, and device interrupts stay on CPU 0.

**Tech Stack:** C (K&R / gnu89, Apple GCC 2.7–2.95 era), i386 and PowerPC assembly in the tree's existing dialects, Mach 2.5 / 4.4BSD kernel, DriverKit. Host-side harnesses built with `cc -std=c89 -pedantic -Wall -Wextra -Werror` and GNU make. QEMU (`vm/qemu_boot.py`, `vm/run-q35-uefi.sh`) for i386; a dual-processor G4 with a serial console for ppc.

## Global Constraints

- Match the surrounding dialect: old-style parameter declarations where the file uses them, `#import` where the file uses it, tabs, no prototypes added to files that lack them.
- **The `NCPUS == 1` build must not change behaviour** until Phase 6. Every new machine-dependent file compiles to nothing or to trivially equivalent code under `#if NCPUS > 1` where the existing code does the same; shared-file edits are guarded the same way as the CMU code around them (`#if NCPUS > 1`).
- **Every commit boots.** The `SMP` configuration is booted on QEMU i386 with `-smp 1` after every commit that touches i386 or shared files, and on the ppc build box after every commit that touches ppc or shared files. Boots use a temporary copy of the disk image (`CLAUDE.md` §6).
- BSD code never runs on a secondary CPU. `DEBUG` builds assert `cpu_number() == master_cpu` at the entry points listed in Task 2.4 and in `sleep()`/`tsleep()`.
- Interrupt-level code never takes a sleeping lock and never calls `unix_master()`.
- Firmware supplies register addresses: local APIC base from MADT/MP table, KeyLargo GPIO offsets from the device tree. Constants are fallbacks and print a warning when used.
- `panic()` is not usable before `panic_init()`; early failures halt with the arch idiom (`hlt` loop, `while(1)`).
- `ebx` is reserved by the PIC ABI; any `cpuid` inline asm saves and restores it (see the 2026-07-24 CPU detection plan).
- Host tests use stub headers only (`tools/cpusubtype-test/stub/` pattern); they never include a real `<mach/machine/*.h>`.
- Commit messages: short, human-readable, subsystem prefix (`kernel: `, `drvPExpert: `, `bootefi: `, `vm: `, `docs: `), one to two lines, describe behaviour not files, no trailing metadata.
- Kernel builds on the guest: `powershell -File vm/rhap-vm.ps1 ssh "cd /build/source/src/kernel-7/conf && gnumake SMP"` (Phase 1 adds the `SMP` type). Host tests: `make -C <dir> -f Makefile.host test`.

## Background: what the tree already has

CMU's multiprocessor scheduler, processor sets, per-CPU timers, AST arrays, the
`unix_master()` funnel-by-binding, `slave_main()`/`slave_start()`, printf and
panic locks, and shutdown of other processors are all present under
`NCPUS > 1` and have never been compiled in this tree. Simple locks are real
atomics on both architectures (`xchgl`; `lwarx`/`stwcx.` via `test_and_set`).
What is missing is entirely machine-dependent plus a handful of undefined
symbols the CMU code calls: `cause_ast_check()`, `init_ast_check()`,
`slave_config()`, `start_other_cpus()`, `ns_hardclock_init()`, and
`<machine/cpu_number.h>`. The spec's "Current state" section has the full
inventory with file references.

### Task 2.3: ppc `cpu_number()`, per-CPU interrupt stacks and `per_proc_info` for every slot

**Files:**
- Modify: `src/kernel-7/machdep/ppc/exception.h`, `cpu_number.h`, `genassym.c`, `start.s`, `hw_exception.s`, `cswtch.s`

**Interfaces:**
- `struct per_proc_info` gains `unsigned int cpu_number;` and `unsigned int istackptr;` (the per-CPU replacement for the global).
- `cpu_number()`:

```c
static __inline__ int cpu_number(void)
{
    struct per_proc_info *pp;
    __asm__ volatile("mfsprg %0,0" : "=r" (pp));
    return (pp->cpu_number);
}
```

  This dereferences the *physical* address in `sprg0`, which is only valid because the kernel data segment is identity-mapped by BAT. `powermac_vm_init.c` asserts `(unsigned)&per_proc_info[0] == per_proc_info[0].virt_per_proc_info`'s physical translation at boot and halts with a message if not; if that assertion ever fails on a machine, the fallback is to read `PP_VIRT_PER_PROC` through a BAT-mapped alias, and the plan is amended then, not speculatively now.

- [ ] **Step 1: Extend `per_proc_info` and `genassym`**

Add the two fields at the end of the struct (before `fpu_pcb` is fine; the assembly uses symbolic offsets). Emit `PP_CPU_NUMBER` and `PP_ISTACKPTR`.

### Task 5.1: i386 TLB shootdown

**Files:**
- Modify: `src/kernel-7/machdep/i386/pmap.h` (`cpus_using` bitmask, `PMAP_ACTIVATE`/`PMAP_DEACTIVATE` with atomic `or`/`and`), `pmap.c` (every `flush_tlb()`/`invlpg()` site after a mapping change: `:184`, `:187`, `:288` and the rest of `grep -n "flush_tlb\|invlpg" pmap.c`), `mp.c` (`IPI_VECTOR_TLB` handler), `lapic.c`

**Interfaces:**

```c
/* pmap.h */
#define PMAP_ACTIVATE(pmap, thread, cpu)   atomic_or(&(pmap)->cpus_using, 1 << (cpu))
#define PMAP_DEACTIVATE(pmap, thread, cpu) atomic_and(&(pmap)->cpus_using, ~(1 << (cpu)))
void pmap_update_tlbs(pmap_t pmap, vm_offset_t start, vm_offset_t end);
```

`pmap_update_tlbs()` computes `others = pmap->cpus_using & ~(1 << cpu_number())` (the kernel pmap uses all running CPUs), stores `start`/`end` in a per-CPU shootdown request block, sends `IPI_VECTOR_TLB` to each, and spins until each target increments its acknowledgement counter. The handler flushes (`invlpg` per page under 32 pages, else `flush_tlb()`), increments the counter, EOIs. The requester runs with interrupts enabled while spinning so it can service another CPU's shootdown (deadlock avoidance, Mach 3 style).

- [ ] **Step 2: Bitmask and hooks**; `pmap_destroy()` asserts `cpus_using == 0`.
