# NetBSD ext2 Filesystem and Tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add native read/write ext2 data volumes to both RhapsodiOS kernels and ship their mount, format, check, and inspection tools in an `ext2fs` APK.

**Architecture:** Port the pinned NetBSD 2.0 branch's ext2 core into `kernel-7/bsd/ext2fs` and register it statically, following FAT/HFS. Package NetBSD's mount helper, e2fsprogs 1.35, native wrappers, and the filesystem helper under `src/ext2fs-1`. Preserve NetBSD's disk conversion and mapping through a Rhapsody inode adapter and audited local UFS/Mach interfaces.

**Tech Stack:** Darwin 0.3 BSD VFS and Mach paging, C89 and the Rhapsody compiler, ProjectBuilder/pb_makefiles, GNU configure/make, rbuild/apk, Python/pytest host harnesses, QEMU i386 and a native PPC guest.

**Spec:** [Approved design](../specs/2026-10-05-ext2fs-design.md)

## Global Constraints

- Core: `src/kernel-7/bsd/ext2fs/`; tools: `src/ext2fs-1/`; package: `ext2fs`.
- NetBSD `netbsd-2-0`: `c90afb5a84a9c36a5c076093afade8e63ed2b6a9` (branch maintenance snapshot, not the initial release).
- e2fsprogs `E2FSPROGS-1_35`: `e55043f87678587a03895d9629efb1c5a659d392`.
- Keep original NetBSD BSD notices/acknowledgements, e2fsprogs `COPYING` and library notices, checksum records, and ordered tool patches. Do not import NetBSD's checker in addition to e2fsck.
- Build kernels separately for i386 and PPC; build a universal tools package with separate per-CPU configure/object directories and private static support libraries.
- Static filesystem name `ext2fs`, type number **18**, flag `MNT_LOCAL`, no root-mount callback; append `VT_EXT2FS` without renumbering existing tags.
- Ext2 revisions **0/1**, inode size **128**, revision-1 first ordinary inode **11**, block sizes **1024/2048/4096**.
- Allowed masks: compat **0**, incompat **0x0002** (`filetype`), ro-compat **0x0001** (`sparse_super`); reject all other feature bits for this first profile.
- File-size limit **2147483647 bytes**; validate device bounds and arithmetic before metadata reads or writes.
- Device capacity comes from `DKIOCGPARTINFO` in exported `bsd/dev/disk.h`: `_IOR('d',29,struct disk_partition_info)`, with `u_int32_t block_size` and `u_int32_t block_count`. Query the selected logical partition object; reject live/whole-drive, unavailable, nonpositive or out-of-range capacities. Preserve legacy `DKIOCBLKSIZE`/`DKIOCNUMBLKS` semantics and never use their whole-drive size as partition bounds.
- Writable mounts require a clean volume. Mark dirty before mutations; mark clean only after successful final flush and unmount.
- No boot support, journal replay, ext4 extensions, quotas, NFS export, online resizing, kernel server, or general fsck dispatcher.
- Use disposable data images and private root-image copies. Native runs on both CPUs are required; skipped or unavailable runs are not acceptance.
- Milestone scheduling: Tasks 1-8 run required native cases on available guests and carry every unavailable case into Task 9 with its CPU, scenario and missing evidence recorded. Both-CPU build requirements remain in force. This permits implementation to proceed; final acceptance stays incomplete until every required native case passes.
- Follow `CLAUDE.md`; preserve unrelated changes and stage only each task's files. Commit messages begin `kernel:`, `ext2fs:`, or `vm:` and contain no metadata.

## Review Focus

1. A mounted block device accessed through a raw or `/private/dev` alias must remain protected from format/repair (Task 7).
2. Truncated metadata and enormous shift/count fields must fail before allocation, overflow, or out-of-device I/O (Tasks 1 and 3).
3. Labels and paths containing spaces, metacharacters, or a full 16-byte unterminated label must remain data, not shell syntax or overreads (Tasks 7 and 8).
4. Writes at the file-size limit or during ENOSPC must return the correct error/short count and preserve the committed prefix (Task 4).
5. Failed sync, failed clean-bit writes, and interrupted writable sessions must never leave a falsely clean mountable image (Task 5).

## Verification conventions

Commands below are planned checks, not results already obtained. Host Python
commands run from the repository root. Native commands run in the build/test
guest, with paths adjusted to the configured `vm.conf` rather than its secrets
being copied into documentation.

For isolated builds, use the existing guest commands:

```sh
PATH=/build/tools/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin; export PATH
rbuild kernel --state /build/state-ext2fs --arch i386 /build/src /build/repo /build/ext2fs-kernel-i386
rbuild kernel --state /build/state-ext2fs --arch ppc /build/src /build/repo /build/ext2fs-kernel-ppc
rbuild buildpackage --state /build/state-ext2fs --dir --target all /build/src/ext2fs-1 /build/repo /build/ext2fs-tools
```

Sync only changed projects with `vm/sync-src.ps1 -Path kernel-7` or
`-Path ext2fs-1`. Kernel outputs are APKs: extract the actual product named by
the build log, rather than guessing a package filename. Use
`vm/ufs-e2e-image.py GOLDEN KERNEL OUT` to install the i386 kernel into a new
private image under `vm/work/ext2fs/`, and set `RHAP_TEST_IMAGE` to that absolute
path. Use `RHAP_VM_ASSETS` when an isolated checkout lacks untracked VM assets.

The new native runner's interface is:

```sh
sh tests/run-native.sh CASE BLOCK_DEVICE RAW_DEVICE MOUNT_POINT
```

It requires explicit disposable devices and a dedicated mount point, rejects
the current root device/mount, and reports `EXT2FS TEST PASS CASE` only after
all assertions. Nonzero status, missing final marker, timeouts, missing assets,
or kernel panics mean failure. The i386 host runner records this status and
serial/results-disk evidence; PPC executes the same cases natively and copies
back the unmounted data volume and logs for independent checking.

## Task 1: Import sources with a tested disk-format contract

**Files:** Create the core import, headers, provenance, codecs, bitmap helper,
and native disk-test files listed in the map. Do not enable the kernel option
yet or add the userland package to `src/Manifest`.

**Interfaces:**
- `int ext2_super_decode(const void *raw, size_t len, struct ext2fs *out)` consumes at least 1024 bytes and produces host-order scalar fields using `e2fs_sbload`; short input returns `EINVAL`. Copy unaligned input to an aligned temporary before swapping.
- `void ext2_super_encode(const struct ext2fs *in, void *raw)` uses `e2fs_sbsave` to write the 1024-byte superblock, preserving UUID, label, and reserved bytes. Assert the imported superblock and disk inode sizes are 1024 and 128 respectively.
- `int ext2_validate_super(const struct ext2fs *es, u_int64_t device_bytes, int writable)` returns 0 or a BSD error; zero/unknown device size is an error, not permission to skip bounds checks. Revision 0 implies inode size 128 and first ordinary inode 11, regardless of unused dynamic-revision fields.
- `u_int16_t ext2_get_le16(const void *p)`, `u_int32_t ext2_get_le32(const void *p)`, `void ext2_put_le16(void *p, u_int16_t v)`, `void ext2_put_le32(void *p, u_int32_t v)` work on unaligned bytes.
- `int ext2_test_bit(unsigned bit, const u_char *map)`, `int ext2_set_bit(unsigned bit, u_char *map)`, `int ext2_clear_bit(unsigned bit, u_char *map)` use byte `bit / 8`, mask `1 << (bit % 8)`; mutation functions return the previous bit value. Callers validate bit bounds.

- [ ] **Step 1: Write `disk_test.c` tests `test_super_profile`, `test_short_super`, `test_bad_geometry`, `test_metadata_byte_order`, and `test_bitmap_boundaries`.** Assert magic `0xef53`, masks `(0,2,1)`, inode size 128, first inode 11, blocks 1024/2048/4096, and rejection of inode size 256, rev 2, compat journal `0x4`, incompat recovery `0x4`, ro-compat large-file `0x2`, and block shift 31. Revision 0 ignores unused revision-1 inode fields. Assert `decode(raw,1023,...) == EINVAL`, `validate(...,0,...) != 0`, and `validate(...,volume_bytes - 1,...) != 0`. Set reserved bytes to nonzero sentinels and assert load/save preserves them with separate and aliased buffers. Check set/clear of bits 0,7,8,31,32 and a last valid bitmap bit; preserve neighboring bytes.
- [ ] **Step 2: Run `make -C src/kernel-7/bsd/ext2fs/tests check` on the native build guest.** Initially fail because the production codec/helper is absent. The Makefile builds against the target's real exported headers and production `ext2_disk.c`; do not substitute a Python implementation.
- [ ] **Step 3: Import the exact upstream files and implement the interfaces.** Populate `ORIGIN` with immutable URLs/checksums, preserve notices, and record the renamed format header and ten-unit compiled inventory. Adapt unavailable bswap/cdefs includes and guard kernel-only headers so codecs compile in userland. Retain NetBSD load/save and pointer accessors; initialize the entire destination record before selectively swapping group/inode fields, preserving reserved bytes and block/fast-symlink bytes. Separate overflow checks from arithmetic; validate group counts, bitmap capacities, inode-table bounds, block/fragment equality, and sector conversion before allocating buffers.

Test group descriptors, inode fields, directory headers, and indirect pointers through their production codec paths, not merely a superblock round trip.

**Interfaces:** `ext2fs_sync`/`ext2fs_unmount` retain Task 2 signatures.
`int ext2_buf_write(struct buf *bp, int waitfor)` centralizes ext2's synchronous
buffer-write result. The first profile waits for ext2 data and metadata writes,
including `MNT_NOWAIT` requests, so errors remain attributable before buffer
ownership disappears; document this blocking and throughput tradeoff. Attribute
device-vnode writes to their ext2 mount explicitly where needed, and return
pre-admission failures directly. Ordinary validation and allocation refusals do
not become sticky I/O errors. A test-only build macro
`EXT2FS_TEST_IO` enables `int ext2_test_write_error(struct buf *)` with a
per-test fail-after count initialized by `fault_io.c`. A private root-only
control-partition vnode ioctl may arm a selected disposable target before its
mount, and inject a selected successful-short inode read. Record target, phase,
matched writes, residual and buffer releases; production code has no test
control interface or additional package payload. RW-to-RO may conservatively

exempt only the actual root directory, preserve the old mode and usable handles

`persistence`, `remount`, `busy`, `ioerror`, `dirty-refusal`, `recovery`.

- [ ] **Step 1: Add failing cases for RW-to-RO-to-RW updates, busy unmount, failed initial dirty-state write, failed metadata sync, and failed final clean-state write.** Assert failed admission does not publish a live mount, busy unmount leaves files usable, and write errors propagate. Exercise repeated fail/mount cycles for leaked vnode references and allocations.
- [ ] **Step 2: Run the cases before correcting the relevant error paths.** Build the I/O-fault kernel only into private test outputs. Use fault counts to hit the initial superblock write, an allocation/inode write, and final clean write deterministically; record which write failed.
- [ ] **Step 3: Implement dirty/clean ordering and propagate I/O errors.** Keep a per-mount error latch so an earlier delayed write failure cannot be hidden by a later successful superblock write. Flush data, bitmap/group counters, inodes, and superblock in the required order; do not free mount state prematurely on unmount failure. Honor RO/RW update checks and cleanup.
- [ ] **Step 4: Run an interrupted session against a disposable data image.** Persist the dirty marker and known fsynced files, then terminate only the test guest. On reboot assert normal RW admission fails; run offline `e2fsck -p`, preserving its result bits, then `e2fsck -fn` and remount. Compare fsynced payloads and filesystem consistency; do not assert durability for unflushed application data.
- [ ] **Step 5: Run `persistence remount busy ioerror dirty-refusal recovery` on both CPUs.** Restart the guest between write/read phases. ## Task 7: Add native format/check wrappers and helper protocol

**Interfaces:**
- `newfs_ext2fs [-b 1024|2048|4096] [-L label] [-m percent] special [blocks]`; defaults revision 1, inode size 128, blocks 1024, reserved percentage 5, masks `(0,2,1)`. It invokes mke2fs with explicit profile flags, rejecting unsupported native options and mounted targets before execution.
- `fsck_ext2fs [-n|-y|-p] [-f] [-v] special` translates to e2fsck; conflicting repair modes are invalid. Preserve its exit bitmask: 0 clean, 1 corrected, 2 reboot advised, 4 errors remain, 8 operational failure, 16 usage, 32 cancelled, 128 library error.

Repair maps bitmasks with operational/usage/signal failures to `FSUR_IO_FAIL`, remaining-error bit 4 to `FSUR_IO_UNCLEAN`, and success/corrected/reboot bits alone to `FSUR_IO_SUCCESS`, reporting reboot advice. ## Plan review and execution handoff

This is one plan because the disk contract, kernel driver, wrappers, and tools
share the same mount/format guarantees. The milestones have separate checks,
but shipping only the RO milestone does not meet the approved scope.

No implementation has been performed while writing this plan. Review it
before execution and choose either subagent-driven task/reviewer gates or
native execution by the current agent followed by a whole-branch review.
Subagent-driven execution is recommended for this port: errors in the shared
UFS interfaces or clean-state ordering can corrupt data, and the nine tasks
provide useful independent review boundaries. Neither execution method removes
the native i386/PPC and independent-checker acceptance requirements.
