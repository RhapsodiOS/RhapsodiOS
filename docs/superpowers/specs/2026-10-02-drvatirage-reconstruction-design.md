# drvATIRage i386 decompilation and reconstruction

## Intent and scope

Reconstruct `src/drivers-i386/video/drvATIRage` from Apple's shipped i386
`ATIRageDisplayDriver_reloc`, using IDA and the repository's binrecon tools.
The user requested the reconstruction and, on 2026-10-02, explicitly requested
both this design spec and its implementation plan. That authorizes preparing
both documents in this pass. These documents describe future implementation;
the driver source has not yet been reconstructed.

The complete denominator is **62 routines: 60 handwritten and two generated**.
IDA initially recovered 61 functions. The additional routine is the 203-byte
`__ATIbios32` assembly thunk at `0x2f20`, which IDA disassembled but did not
recognize as a function because its far-call operand is embedded data. The
60 handwritten routines comprise 48 Objective-C methods and 12 C/assembly
routines. Exporting the initial 61 pseudocode bodies is useful evidence, but
does not establish full code coverage or reconstruction completion.

Reconstruct the ATI and ATI_BIOS classes, the ATI ProgramDAC and ATI_BIOS
Private categories, PCI resource repair, display modes, drawing engine,
cursor synchronization, gamma/brightness, BIOS services, descriptor handling,
BIOS thunk, configuration tables and localized resources. Preserve the shipped
interfaces and behavior. Other drivers and shared kernel/DriverKit behavior
are outside this change. Do not introduce new hardware support or silently
correct quirks in Apple's implementation.

## 2. Established ABI and build defects

The current source declares `ATIRageDisplayDriver`, three hard-coded 8-bit
modes, fabricated ATI-prefixed methods and a Rage 128 register path. The shipped
configuration names the class `ATI`, and the binary has a different class
layout and method set. Replace the bodies and declarations from evidence.
The current `Load_Commands.sect` contains section names; the reference's
`Loaded Server,Load Commands` contains the `WIRE` directive, with no MIG
handler/server interface.

Raw Objective-C metadata confirms:

| Class | Superclass | Instance size |
| --- | --- | ---: |
| `ATI` | `IOFrameBufferDisplay` | 624 |
| `ATI_BIOS` | `Object` | 16 |
| `ATIRageDisplayDriverVersion` | `IODevice` | 264 |
| `ATIRageDisplayDriverKernelServerInstance` | `Object` | 4 |

The last two classes are generated by the Kernel Server build. Their methods
are at `0x2154` and `0x2160`; the version method returns 500. Generate them
through the existing build rules, preserving their reference role and order.

The proposed source units preserve the observed text order: main ATI code,
generated instance methods, ATI_BIOS code, ATIbios16 wrapper, assembly thunk.
This order is supported by binary addresses, rather than a claim to know every
original source filename. The main implementation includes static helper
forward declarations so definitions can remain in reference address order.

ThinkPad `LOADABLES +=` postamble pattern can do this after separately compiling
the extra objects; adding them to `CLASSES` would put them before the instance
object. Confirm the actual linker object list before accepting the build.

## 4. Behavioral reconstruction requirements

### Initialization, PCI and modes

Recover PCI identification through the device description and BIOS discovery,
BAR sizing/restoration, resource alignment, conflict handling and the `FB
Address` override. Preserve I/O versus memory BAR masks and the exact counts
passed to range-list methods. Several arguments look odd in pseudocode;
resolve them from call-site instructions before transcription.

Initialize the real BIOS object, test the scratch register with `0x55555555`
and `0xaaaaaaaa`, retrieve BIOS query data, and derive feature flags and memory
size from it. The framebuffer mapping requests 8 MiB; the register aperture is
at framebuffer + `0x7ffc00`. Neither is a VGA `0xa0000` framebuffer mapping.
Preserve error messages and cleanup paths from the reference.

Recover all 72 IODisplayInfo entries and their 18 CRTC records directly from
data and relocations. Preserve order, pixel encodings, refresh rates, flags,
private parameters, required memory and validity fields. DriverKit's enum
values are not literal bits-per-pixel. Use `displayDefs.h` to interpret them.
The mode table is mutable: update framebuffer pointers, supported gamma flags,
32-bit channel ordering, and memory availability as the reference does.

Recover `isModeValid:`, pending mode handling, state transitions and VRAM
verification without added recovery. Pin boundary behavior including the
reference's mode-range status 16, unsupported-format status 64, memory status
2, and `memSizeToBytes(5) == 8,386,560` (8 MiB minus 2 KiB). Review negative
indices and query failures using the original signedness; do not assume a new
validation policy.

### Drawing and cursor synchronization

Recover the MMIO access widths and write order in waitForFIFO, waitForIdle,
doBlit, doFill, initEngine and resetEngine. Preserve overlap-dependent copy
directions, saved/restored registers and the pixel-depth constants. The FIFO
poll and idle poll have different termination behavior. Record the idle timeout
condition from instructions, including the increment/comparison order.

The three cursor methods wait for engine idle before forwarding to the
superclass. The parameter dispatcher recognizes `IODisplayDoBlit` with six
values, `IODisplayDoFill` with five, and `IOGetDisplaySynced` with one; other
names/counts forward to the superclass. Do not invent hardware cursor support.

### Gamma and transfer tables

Recover the ProgramDAC category's three methods and its two C helpers,
including the exact `isATI68880RevC` symbol spelling. Preserve Sparse/Dense
RAMDAC overrides, ASIC/DAC tests, byte extraction, brightness range 0..64,
allocation ownership and replication of palette entries. Recover both gamma
arrays exactly; do not replace them with identity ramps. Trace the reference's
behavior for zero/negative/non-dividing transfer counts before documenting
their input assumptions. Reconstruction is not authorization to change those
behaviors.

### ATI BIOS and assembly

Recover all 26 ATI_BIOS methods, including its seven Private methods, and the
ATIbios16 wrapper. The BIOS signature scan, query services, CRTC/VGA/aperture,
DPMS/APM and refresh operations remain individually reviewable. `querySize:size:`
returns 4096, and `changeRefreshRate:` returns status 3; these small functions
still belong in the coverage inventory.

The BIOS register block is 48 bytes. Derive each register/segment/flags/entry
field from accesses and metadata. Descriptor slots use selectors `0x80`,
`0x88`, `0x90`, `0x98`; stack allocation is 2048 bytes. Preserve descriptor
save/restore, address translation, granularity bits, data-size limits and
error paths. Use a named layout for the 36-byte private block without changing
its offsets. Decode the gdt symbol through existing kernel headers.

Write the 203-byte thunk as symbolic assembly. It preserves general and
segment registers and flags, patches the far-call offset/selector at
`0x2f7a`/`0x2f7e`, transfers registers through the caller's block and restores
the caller state. Preserve those immediate-data fields, `cli`, and stack
discipline. Do not paste a raw binary blob or copy relocated absolute addresses
into source. Compare the assembled routine byte-for-byte after accounting for
relocation fields, even if IDA still refuses to define it as a function.

## 5. Static data and packaged resources

Recover all reference data, including gamma8/gamma16, bitsPerPixelValues,
colorConfigValues, both refresh lists, ATI_modeToRefreshRatesTable, 18 named
crt records, AtiModeList, AtiModeListCount, ValidModeList, ABReturnValues,

ATI_dacTypeValues, ATI_busTypeValues, BIOS offsets/selectors, kernDataSel,
thunk scratch storage and I/O delay counters. Preserve local/external binding,
initial values, string content and pointer targets. Classify padding separately
from data; matching table counts alone is insufficient.

Restore the reference Default.table, Display.modes, PCI4Mb/PCI6Mb/PCI8Mb
tables and modes, four localized string files, Help/TableOfContents.rtf and
the four ATI help bundles. Preserve paths and case, including the shipped
resource filenames. Resource declarations must actually stage these files;
merely adding files is insufficient. Treat Driver Version and generated
VERS_STRING/VERS_NUM as build metadata and report their differences explicitly.
The companion executable's 34-byte text section is generated bundle glue, not a second
handwritten display driver. Require its presence in the final staged package.

## 6. Verification and evidence rules

Reconcile raw text symbols, Objective-C method IMPs, IDA boundaries and every
text gap. The reference contract records all 62 routines, generated ownership,
section identities, ABI, static-data descriptions and supplemental thunk range.
The closed binrecon source-map schema is unchanged. If the thunk remains outside
IDA's partition, record its source address/extent/location in the separate
contract and check that range explicitly. The ordinary source map should map
all 59 handwritten IDA functions; its only permitted generated omissions are
the two instance methods. If a later analyzer recognizes the thunk, reconcile
the source map and denominator without double counting it.

Use binrecon's semantic `load_source_map` validation with the actual saved
analysis and repository root. Maintain an entry for every routine in the
ledger, with the supplemental entry identified in findings. Pseudocode or
compilation alone cannot advance a function to assembly-matched. Reviewer
fields name the actual reviewer; do not attribute review to the user by default.

Build fresh i386 objects and the kernel artifact in the historical compiler
environment. Capture compiler/linker versions, flags, object ordering, build
exit statuses and hashes. A pre-existing artifact or a successful earlier run
cannot satisfy the gate. A dedicated staging directory holds the rebuilt
_reloc, companion executable and complete resources.

Run the IDA/binrecon comparison with a profile containing both reference and
rebuilt artifacts and `normalized-functions` acceptance. Keep the reference-only
profile usable; create a separate comparison profile. Supplement it with ABI,
selector, class-reference, import, static-data and assembly checks, using existing
binrecon tools where possible. Existing selector_check exit 0 does not imply
its reported missing/extra selector lists are empty; assert those lists too.

### Completion gates

1. All 62 routines have a source/generated owner, evidence, and reviewed behavior;
   all 202 initially uncovered text bytes have an explained classification.
2. Every handwritten routine has readable source and no unresolved placeholder.
3. Rebuilt classes, categories, selectors, method encodings and instance layouts
   match the reference ABI. Imported class references retain direct linkage.
4. All static tables and relocation targets match, and the 203-byte thunk matches
   under relocation-aware byte comparison.
5. A fresh build links and stages the complete driver package with no unexplained
   missing symbol, reference string or unresolved kernel import.
6. Binrecon reports a complete reference/rebuilt run and passing normalized-function
   acceptance. Investigate every failure; do not waive it silently as compiler noise.
7. Findings and the ledger describe the exact evidence and any generated metadata
   differences. An unmet gate remains an unmet gate, not a claim of completion.

Hardware testing is a separate result. Generic QEMU VGA/Cirrus output does not
exercise an ATI Rage BIOS or drawing engine. If compatible hardware/emulation
is available, exercise initialization, supported display modes, overlap blits,
fills, cursor forwarding, gamma/brightness and VGA restoration on a temporary
disk image. Otherwise report the reconstruction's static/build evidence and
state that ATI hardware execution remains unverified.
