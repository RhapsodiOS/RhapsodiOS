# Additional Screamer profiles, 2026-10-18

Continuation of the approved driver plan, based on `0718f5f6d`. This implements
source-backed firmware/profile/codec paths for the requested candidates. It
does not establish physical audio, complete OS boots or system sleep/wake.

## Evidence recovered

[SOURCES.md](../../SOURCES.md) links the first-hand Lombard/Pismo device-tree
captures, official iMac firmware, pinned Apple fallback table and active power
and mux implementations. Firmware-derived iMac tables are distinguished from
live captures. Lombard's BootROM has no sound objects; its fallback is Apple's
explicit PowerBook1,1 patch, guarded by exact model/chip/bus identifiers.
No complete PowerMac3,2 capture was located; it still requires complete explicit
firmware at attachment. No generic routing fallback was introduced.

## Reproduced failures and review

Profile tests first failed for missing Proj6/10, Pangea and the actual Pismo/
iMac object forms. Runtime tests first failed for their distinct timing, mux
and front-headphone port behavior. Backend family tests first failed 54
assertions; partial-off retry tests reproduced eight failures before active
state invalidation was corrected. PCM vectors first failed 28 assertions
against an unimplemented transformation.

The period adapter test reproduced a pre-existing private-encoding mismatch:
IOAudio negotiates Linear16 as internal enum 0, while the adapter expected a
public NX tag. The corrected adapter consumes the private enum and the test
uses the framework's actual numeric contract.

One fresh whole-branch review found an Important lock recursion: capture queue
drain during power-down could invoke the PCM hook while `operationLock` was
already held. A nonrecursive test lock reproduced the failure. The hook now
reads immutable profile data and committed aligned-word route/input snapshots
without acquiring that lock; the same held-lock callback regression passes.
Live input changes remain refused. One correction pass was made; no second
review or unresolved code finding is represented as an independent approval.

## Remaining acceptance

Rebuild/link and boot the updated kernel DriverKit audio implementation and
cache provider with the new Platform Expert before installing the driver.
Object compilation is not a complete linked/booted PPC kernel result.
Every machine still needs the physical checklist in [VALIDATION.md](../../VALIDATION.md):
signals, pitch/channel order, input gain, all connectors, sustained duplex and
start/stop cycles. System power acceptance still depends on replacing the PPC
APM stub and proving callback ordering; native clients restart stopped streams
after wake. APK installation and the pre-existing full AWACS build limitations
from the original evidence remain pending. No new successful APK, whole AWACS
bundle or hardware result is claimed.
