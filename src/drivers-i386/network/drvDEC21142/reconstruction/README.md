# DEC21142 reconstruction

This i386 source reconstruction is based on
`DEC21142Network.config/DEC21142Network_reloc` (45,728 bytes, SHA-256
`B8FA440177799B9510A0AD5ED5C3C71DA3E9D146F561CE5439F84E2D65B1C7F9`). IDA
9.4 identified 50 function boundaries. The source map covers 48 authored
functions; the other two methods are generated by the legacy Kernel Server
build (`kernelServerInstance` and `driverKitVersionForDEC21142Network`).

The reconstruction restores the `IOEthernet` superclass and 844-byte instance
layout, recovers the source/header selector ABI, and fixes the DMA translation,
SROM and connector setup, reset lifecycle, transmit/receive descriptor rings,
debugger packet paths, and network-interface accounting. In particular, RX
descriptor validation now checks the first/last and error-summary bits in the
correct status byte, and descriptor physical addresses use the DriverKit
output-parameter API.

Several cleanup and error-path quirks are retained because IDA shows them in
the reference: a failed TX DMA mapping leaves the freed packet pointer in its
ring slot, `free` does not release `KDB_txBuf` or `transmitQueue`, and
initialization returns `self` without checking the result of network
attachment. `_initRegisters` is also a `void` method, so its physical-address
conversion failure is not propagated by `_init`. These paths have not been
validated in a rebuilt driver.

Binrecon's independent IDA and angr analyses found different function
partitions (50 versus 120 functions). Its analysis run has no rebuilt candidate
and reports zero comparisons, so the profile's `normalized-functions`
acceptance is not met. `source-map.json` follows the IDA partition, and
`verify_evidence.py` checks its coverage while explicitly accounting for the
two build-generated methods. Analysis products are stored under
`tools/binrecon/out/dec21142` and are not committed.

## Verification

Run from the repository root:

```powershell
\.venv-binrecon\Scripts\python.exe -m pytest src/drivers-i386/network/drvDEC21142/reconstruction/tests -q
$env:PYTHONPATH = "tools/binrecon"
$env:BINRECON_REFERENCE = "C:\path\to\DEC21142Network_reloc"
\.venv-binrecon\Scripts\python.exe -m binrecon validate --profile tools/binrecon/profiles/dec21142.json
\.venv-binrecon\Scripts\python.exe src/drivers-i386/network/drvDEC21142/reconstruction/verify_evidence.py --analysis tools/binrecon/out/dec21142/published/analysis-reference-ida.json --source-map src/drivers-i386/network/drvDEC21142/reconstruction/source-map.json --repo-root .
```

To regenerate the analysis artifacts, run `binrecon analyze --profile
tools/binrecon/profiles/dec21142.json` after setting the two environment
variables above. A rebuilt i386 relocatable is not available, so
`verify_binary.py` has not been run against a rebuilt image; hardware behavior
is also unverified.
