# drvDEC21X4X reconstruction

The reference is Apple's i386 `DEC21X4XNetwork_reloc` (85,400 bytes; SHA-256
`2F51BB05C111BB01E7E4D2766A1BD23DC2CEAEB641C89057FE580F8C23465180`). IDA
enumerates 122 routines: 43 handwritten Objective-C methods, 76 local C
helpers, the external `IOUpdateDescriptorFromNetBuf` DriverKit helper, and two
Kernel Server accessors generated by the project. The 43 source selectors
match the handwritten reference selectors, and all 76 local C routines map to
one source definition. IDA's class layout is restored
from `ioBase` at `0x174` through `MediaCapableSaved` at `0x338`; adapter state
is retained at `0x334` and read from that field by the controller methods.

The adapter tables, localized strings, inspector nib, and DriverHelp resources
are present. The Project Builder manifests now include the inspector nib and
help resources, and the source imports the in-tree `IOEthernet` and netbuf
interfaces. Resource checks compare the reference files byte-for-byte, except
that `Default.table`'s generated Driver Version and Version keys are ignored.

Run the reference checks from the repository root on Windows:

```powershell
$env:PYTHONPATH = 'tools/binrecon'
$env:BINRECON_REFERENCE = 'C:/path/to/DEC21X4XNetwork.config/DEC21X4XNetwork_reloc'
.\.venv-binrecon\Scripts\python.exe -m unittest src.drivers-i386.network.drvDEC21X4X.reconstruction.test_reference -v
```

All 22 source and bundle checks pass. They also enforce unique C helper
definitions across both translation units, ensure the media auto-detect helpers
come from the recovered state machine, and check the PHY link/negotiation result
composition. The duplicate MII auto-detect stubs were removed, the CSR9 port
access in `WriteMii` was restored, the link-status path was corrected from IDA
pseudocode, and the header's adapter declarations now use the 32-bit i386
pointer ABI used by the source. The SROM parser and its fixed/extended block
helpers now follow the recovered byte cursor, info-leaf offset, and block
length semantics. The media-register initializer follows the recovered
chip-revision branches.

BinRecon's IDA pass completed, but the angr analyzer rejects relocation 968 at
the final generated accessor because the relocation extends beyond angr's
decoded one-byte instruction. There is no rebuilt binary for function
comparison. The source reconstruction is complete, while the i386 APK build
and hardware behavior remain unverified.
