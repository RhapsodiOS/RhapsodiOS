# drvEtherLink3 reconstruction

This source is reconstructed from Apple's i386 `EtherLink3_reloc` reference
(SHA-256 `F245A073FB1E54837C9B3B3C709B87D89645E123BB291BAFF659ABC5DA9C4EFD`,
51,868 bytes). IDA identifies 40 functions: 32 hand-written Objective-C
methods, two project-generated Kernel Server accessors, and six C helpers.
The two generated accessors return the server instance and DriverKit version
500; Project Builder emits them from the Kernel Server project type.

The recovered adapter state begins at instance offset `0x174`. The header
records every field through `inputErrors` at `0x1f0`, including the four
16-byte packet queues. The driver uses windowed EtherLink III PIO, a 32-buffer
receive pool, a 16-packet transmit queue, and a 64-entry transmit completion
queue. The ISA, EISA, PCMCIA, and ISA PnP probes follow the reference. The four
board tables, four localized string files, and DriverHelp resources are
restored; resource files match Apple's bundle byte-for-byte.

Run the reference-driven source checks from the repository root on Windows:

```powershell
$env:PYTHONPATH = 'tools/binrecon'
$env:BINRECON_REFERENCE = 'C:/path/to/EtherLink3.config/EtherLink3_reloc'
.\.venv-binrecon\Scripts\python.exe -m unittest src.drivers-i386.network.drvEtherLink3.reconstruction.test_reference -v
```

The checks compare source selectors and project resource manifests with the
reference. They permit only the two accessors generated by the project type.
`tools/binrecon/profiles/etherlink3.json` runs IDA and angr on the reference;
the normalized consensus reports disagreements between analyzers, so its
analysis is evidence for review and does not by itself certify parity.

The local source checks pass (4 tests). A native i386 package build has not
completed: the isolated guest repository is missing a `drivertools` APK, so
that dependency must be built there first. The driver has not been tested on
physical EtherLink III hardware.
