# drvATIMach64 divergences and decisions
## Negative display-mode index guard after v39 (2026-10-05)

Code review found that `setPendingDisplayMode:` and `isModeValid:` rejected
indices at or above the mode count but allowed negative indices to reach
`AtiModeList[modeIndex]`. Both methods now reject negative values before any
table access. Reconstruction tests cover both checks. This is a post-v39 source
hardening change; the recorded v39 package and comparison remain unchanged, and
the modified source still needs a fresh package build before binary parity can
be reassessed.

## `initBIOSBuf:function:` register lifetime follow-up (2026-10-05)

The v27 IDA export shows the reference keeps `ATIBIOSRegisters *` in EBX across
`setupCodeSegments` and `bzero`, then reloads the function byte from
`[ebp+arg_C]` into DL and writes `[ebx+4]` (80 bytes). The v27 rebuild saves the
function byte in BL before the Objective-C call, reloads the buffer pointer
into EDX, and uses a 32-bit store (89 bytes).

Three fresh i386 builds exercised source-level register-lifetime forms. The
v30 artifact (`28B43562618D8181B303A91A9468DFEA1087FCCF74823E39C0E467F796A433C2`,
64,196 bytes) keeps the pointer in EBX and uses the reference's byte store, but
the volatile byte local spills to `[ebp-1]`; the method remains 89 bytes and
BinRecon reports CFG, instruction-shape, and range differences. The v31
artifact (`9C7C57C08B6971271B938CB5DA6D448E0B2DBF488CD3361CF5A4CC5EB6551508`,
64,196 bytes) removes the volatile local, but returns to the BL-byte/EDX-pointer
allocation (83 bytes). A v32 named-register declaration failed with the legacy
NeXT Objective-C compiler. A v33 rebuild then used the compiler-supported
empty EBX constraint; IDA still shows a stack spill and an 89-byte method, so
that extension did not improve parity. Its relocatable is preserved in the
run directory named `fresh-rebuild-register-lifetime-v32-2026-10-05/` with
SHA-256 `66B0D4077E41091D74D4DEA02BB5839F3117DC822BB4F07AD1AA41D65BC719B5`.

The retained source uses the v30 plain C form: a live pointer local plus a
volatile byte local, with no inline assembly. The artifact and comparison
outputs are hash-bound in the corresponding ignored BinRecon run directories.
Across these builds normalized-functions remains false; register and stack
allocation is still a compiler-codegen divergence. Compatible ATI hardware/ROM
validation also remains open.
## Objective-C class-field relocation pairing (2026-10-05)

The v27 reference/rebuilt IDA exports showed that `-[ATI_BIOS initAtSegmentAddress:]` uses the `.ext` field of the `ATI_BIOS` class record for `[super init]`. The reference record starts at `__class+120` and the rebuilt record at `__class+40`; both are identified by relocations to the `Object` superclass string and `ATI_BIOS` class-name string. Follow-up builds and the remaining method findings are documented in the register-lifetime section above.
